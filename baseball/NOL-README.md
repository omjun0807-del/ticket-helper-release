# 기존 야구 헬퍼의 NOL 지원 · 0.1.16

기존 헬퍼 업데이트: https://raw.githubusercontent.com/omjun0807-del/ticket-helper-release/main/baseball/ticketlink-entry.user.js

NOL 0.1.0 별도 설치 파일은 이전 사용자용으로 남겨둡니다. 새로 설치할 때는 기존 야구 헬퍼 통합본을 사용하세요. 이미 별도 NOL 스크립트를 설치했다면 끄고 기존 야구 헬퍼만 켜세요. NOL 설정과 티켓링크 설정은 따로 유지하며 기존 NOL 설정도 불러옵니다.

NOL 스포츠 목록에서 지정한 경기의 예매 버튼을 한 번 누르는 기능입니다. WC 실제 경기 화면과 오픈 정각 자동 진입은 아직 검증하지 않았습니다. 현재 두산 공개 경기 HTML과 사용자 정규시즌 예매 영상을 참고했습니다.

## 사용 순서

1. PC Chrome의 Tampermonkey에서 기존 야구 헬퍼를 0.1.16으로 업데이트하고 페이지를 다시 엽니다. 설치 이름은 업데이트 호환을 위해 기존 Ticketlink 경기 진입 시험판 이름을 유지합니다. NOL 사이트에서는 NOL 모드를 자동으로 사용합니다.
2. 예매할 경기가 실제 목록에 표시되면 경기 날짜·경기 시작 시간·홈팀·원정팀을 화면에 나온 이름으로 입력합니다. 예매 오픈 시각과 경기 시작 시간은 서로 다른 값입니다.
3. ‘경기 버튼 지정’을 누릅니다. 입력과 일치하는 예매 버튼이 하나인 경우만 지정합니다. 비활성 버튼도 지정할 수 있으며, 지정 자체는 예매하지 않습니다. 표시된 경기 내용을 확인하고 ‘경기 일치 확인’을 누릅니다.
4. 예매 오픈 시각을 입력하고 ‘시작 대기’를 누릅니다. PC 현지 시계 기준으로 해당 시각까지 기다립니다. 목록을 자동 새로고침하지 않으며, 오픈 시각 이후 지정한 경기와 일치하는 예매 버튼이 활성화되면 1회 클릭한 뒤 자동 동작을 종료합니다. 오픈 이후 30초 안에 확인하지 못하면 종료합니다.
5. 열린 대기 화면·예매창에서 안내 확인, 보안문자, 좌석 선택을 직접 진행합니다. 버튼 클릭 기록만으로 진입 성공을 판정하지 않습니다.

사용자가 알려준 WC 오픈 일정은 2026-10-13 1차전 14:00, 2차전 15:00(KST)입니다. 실제 경기의 날짜·시작 시간·팀은 WC 목록이 공개되면 확인해야 하며, 정규시즌 두산–롯데 경기를 WC 대신 지정하면 안 됩니다. 목록이 다른 주소나 다른 버튼 형태로 공개되면 추가 대응이 필요할 수 있습니다.

## 동작 범위

https://nol.yanolja.com/ticket/genre/sports 및 그 아래 한 단계의 경기 목록 주소, https://tickets.interpark.com/gates/ticket/숫자 형태의 예매 오픈 대기 주소를 지원합니다. 대기 순번 페이지(/waiting), 좌석(/onestop/seat), 결제 화면에는 스크립트를 주입하지 않습니다. 사용자 영상에서도 예매 버튼 이후 인터파크 대기 화면, 좌석 화면의 여러 안내, 보안문자, 구역 선택을 확인했습니다. 영상은 사용자가 직접 누른 사례이며 헬퍼 자동 진입 시험 결과가 아닙니다.

## WC 오픈 대기 화면

사용자 캡처에서 2026 와일드카드결정전 1차전 - LG vs 두산 상품의 오픈 대기 화면을 확인했습니다. 공개 HTML은 빈 앱 뼈대이고, 공개 앱 자료에는 해당 예매 준비 경로와 ‘예매하기’ 문구가 있습니다. 실제 정각에 활성화된 DOM이나 자동 진입 성공을 확인한 것은 아닙니다. 기존 정규시즌 목록과 다른 상품 기반 화면이므로 별도 지정 방식을 사용합니다.

1. 기존 헬퍼를 업데이트한 뒤 해당 /gates/ticket/ 페이지를 다시 엽니다. 대기 페이지(/waiting)는 새로고침하지 않습니다.
2. ‘현재 상품 지정’을 누르고 표시된 상품 번호·상품명을 확인합니다. 현재는 관찰한 형식의 2026 WC 1·2차전 LG vs 두산 상품만 인식합니다. ‘예매 준비가 완료됐어요’ 화면의 단일 상품·단일 카운트다운 또는 예매 버튼인 경우만 지정합니다. 상품명·번호는 직접 입력하지 않습니다.
3. 예매 오픈 시각을 직접 입력합니다. 1차전은 2026-10-13 14:00:00, 2차전은 15:00:00(KST)입니다. ‘상품 일치 확인’ 후 ‘시작 대기’를 누릅니다.
4. 자동 새로고침 없이 기다립니다. 설정한 시각 이후 상품 번호·상품명이 그대로이며 단 하나의 ‘예매하기’ 버튼이 실제로 활성화된 경우만 1회 클릭합니다. 남은시간 버튼은 클릭하지 않으며, disabled 속성을 제거하지 않습니다. 사용자가 먼저 예매 버튼을 누르면 자동 실행을 취소합니다. 버튼을 한 번 눌렀다는 이유로 진입 성공을 판정하지 않습니다.

확인하지 못한 버튼·상품, 인증 필요·보안문자·오류·대기열에서는 클릭하지 않습니다. 중지·설정 수정·상품 주소 변경·30초 만료·페이지 이탈로 종료합니다. 새로 페이지를 열거나 업데이트하면 상품을 다시 지정하고 대기를 시작하세요. 오픈 대기 모드의 실행/설정은 다른 모드와 구분하며 URL 쿼리·pass_code·대기열 키·계정 정보를 기록하지 않습니다.

설정은 저장하지만 설정을 불러오는 것만으로 실행하지 않습니다. 지정 경기 불일치·버튼 복수·비활성 버튼은 클릭하지 않습니다. 중지·설정 수정·현재 URL 변경·시간 만료·알려진 보안 경고·대기열·보안문자에서는 자동 클릭하지 않습니다. 여러 탭에서 동시에 실행하지 말고 이 탭을 앞에 유지하세요. 서버 시각 보정은 없습니다.

NOL에는 안내 자동 확인·비교 진단을 연결하지 않습니다. 티켓링크의 기존 설정·차단 기록은 수정하지 않습니다. 좌석·예약 제출·결제 자동화, 대기열 키/토큰 접근, 보안문자 처리는 포함하지 않습니다.

## 검증

공개 경기 한 줄을 그대로 보관한 HTML fixture와 jsdom에서 비활성 버튼 지정, 입력 일치 확인, 새로고침 0회, 수동 페이지 재진입 후 실행 보존, 활성화 후 1회 클릭, 설정 복원, 중지·기한·화면 변경·보안문자·대기열 제외, 복수/다른 경기 제외, 저장 항목 분리, 자동 안내 진단 저장 상태 거부를 확인합니다. 생성한 설치 스크립트도 같은 흐름을 실행하며, 대기·좌석 주소에서 자동 동작이 없는지 검사합니다. 통합본에서는 두 사이트의 자동 선택, 기존 설치 이름·업데이트 주소 유지, 이전 NOL 스크립트와 동시 로드되는 두 순서의 중복 클릭 방지도 검사합니다. WC 오픈 대기 화면은 캡처와 공개 UI 문구로 구성한 합성 HTML 및 생성 스크립트에서 단일 상품 지정·카운트다운 미클릭·실제 활성 버튼 1회·수동 클릭 후 중복 방지·오류/인증/복수 후보 제외·쿼리 미저장을 검사합니다. 실제 DOM이나 live 자동 진입 검증을 대신하지 않습니다.

전체 npm test는 기존 tests/baseball-screen.test.js:18의 한화 캡처 JSON 손상으로 실패합니다. 이 파일을 제외한 야구 진입·진단 테스트는 별도로 실행합니다. 실제 WC 자동 진입은 미검증입니다.
